# 引用核验

引用错误在法律文书里是硬伤。本技能把每处引用拆成可核对的断言，逐条回到官方法源比对，输出核验表；不能核实的引用不进入交付件。

## 输入

- 一份待核文书（Markdown/DOCX/PDF 文本），或
- 用户列出的引用清单，或
- 检索阶段留下的 `evidence.jsonl`。

先提取引用，不先评价论证。每处引用记录：文件位置（第几段/第几节）、引用文字、声称的来源、声称的条号/案号、声称的生效时间。

## 核验维度

| 维度 | 要核对什么 | 失败后果 |
|---|---|---|
| 原文 | 引用文字与官方正文逐字一致，省略号与改写不改变含义 | 引文不实 |
| 定位 | 条、款、项、章节编号正确；案号与裁判主文对应 | 指向错误 |
| 版本 | 引用的是现行有效版本；修正案、修订、废止、过渡条款已处理 | 适用旧法 |
| 时点 | 以事实发生时点选择适用法；新旧法衔接有依据 | 法律适用错误 |
| 效力 | 法规效力层级、特别法/一般法关系；案例是否生效、是否被再审/撤销、是否指导性案例 | 权威性错误 |
| 姿态 | 用于裁判依据、参考、背景说明的措辞与来源层级匹配 | 夸大权威 |

## 流程

1. **建清单。** 用表格列出全部引用；同一来源多处引用合并为一条，保留全部位置。
2. **查原文。** 用 `legal-research` 的 ego 流程打开官方法源（国家法律法规数据库、最高法、最高检、裁判文书网等），取正文并落盘。
3. **逐字比对。** 引用文字与原文不一致时，给出差异（增、删、改、断章取义），并给修正后的引文。
4. **核版本与时点。** 记录发布、施行、修改、废止日期；事实发生日早于现行版本时，说明应适用的旧法及依据。
5. **核案例。** 案号、法院、裁判日期、裁判结果、是否生效、是否被撤销/再审、是否指导性/参考性案例；比较案情可比性。
6. **定状态。** 只使用以下四种：
   - `已核验`：原文、定位、版本、效力均已比对通过。
   - `部分核验`：部分维度通过，仍有未决项（写明哪一项）。
   - `未核验`：未能取得官方原文，或只有二手转述。
   - `不适用`：该引用不是法律命题（如事实描述、合同条款），并说明理由。
7. **出表。** 按下面格式输出，并在正文中把 `未核验` 与 `部分核验` 的引用改为“待核”或删除。

```
| # | 位置 | 待核表述 | 来源与定位 | 版本/时点 | 状态 | 差异与修正 |
|---|------|----------|------------|-----------|------|------------|
```

## 判定纪律

- **“索引中不存在”不等于“该条不存在”。** 官方库检索不到时，换关键词、换库、换入口；仍找不到就记 `未核验` 并写明检索路径。
- **“商用库命中”不等于已核验。** 只能作为线索；必须回读官方原文。
- **“记忆中的法条”一律按未核验处理。** 不凭训练记忆补条文、补案号、补日期。
- **案例被引用为裁判依据时，必须确认其效力。** 指导性案例、公报案例、普通生效裁判的引用姿态不同。
- **无法核实的关键结论必须停。** 说明失败的工具、时间、替代路径和受影响的结论，不保留确定性表述。

## 输出

先给核验表，再给三行摘要：已核验 / 部分核验 / 未核验 的数量，阻断交付的条目，以及建议的下一步（补证、改写、删除）。证据写入 `./.legal/research/evidence.jsonl` 或案件目录下的同名文件。

## Sati 检索接线

- 在本项目中，法条原文优先用 `law_search` 检索（宝宸知识库，含法律层级过滤与现行/失效标注）；引用成稿前用 `law_verify` 逐条做形式核验。
- `law_search` / `law_verify` 不可用或未命中时，如实标注「未检索到 / 未做形式核验」，不得以模型记忆补法条。
