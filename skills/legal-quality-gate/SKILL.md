# 交付质量门禁

交付前逐项核对。P0 任一项不通过就**不得交付**，先修正再重跑；P1 项逐条给出通过或已知偏差。

## P0 · 阻断项

| # | 检查 | 判定方法 |
|---|---|---|
| P0-1 | 没有虚构的法条、案号、案例、日期、金额或事实 | 每个具体断言能在证据文件或用户材料中找到出处 |
| P0-2 | 每个法律结论都有可验证来源 | 结论句后附 `[E-…]` 或条号/案号；没有来源的推断已标注“推断” |
| P0-3 | 引用已核验 | 跑 `legal-citation-check`；`未核验` 的引用不得支撑结论 |
| P0-4 | 管辖、地域、时点正确 | 以事实发生地/时点选法；跨地域或新旧法衔接有说明 |
| P0-5 | 主体、请求、抗辩与案件事实一致 | 当事人名称、角色、诉讼请求、合同编号逐处一致 |
| P0-6 | 未越权提供正式法律意见 | 面向非律师用户时保留“不构成正式法律意见”声明；不替代律师签字 |
| P0-7 | 保密与特权 | 收件人范围正确；未把工作成果、内部评估或对方材料发给圈外人 |
| P0-8 | 交付件落在正确目录 | 有案件时在 `matters/<slug>/output/`；无案件时在工作区 `output/`；未覆盖 input |
| P0-9 | 引用文字与原文一致 | 逐字比对；省略不改变含义；译文与原文并列时标明 |

## P1 · 质量项

| # | 检查 | 判定方法 |
|---|---|---|
| P1-1 | 结论先行，结构清晰 | 开头一段给结论与建议；后续按争点/要件展开 |
| P1-2 | 不利权威已处理 | 主动列出相反判例、抗辩与风险，并说明区分理由 |
| P1-3 | 可执行性 | 建议包含主体、动作、期限、所需材料；诉讼/仲裁请求可落地 |
| P1-4 | 数字与日期一致 | 金额、比例、期限在正文、表格、附件中一致；大写与小写一致 |
| P1-5 | 名称与称谓一致 | 当事人简称首次定义；全文统一 |
| P1-6 | 格式与体例 | 标题层级、条号格式、引用格式、落款日期符合用户偏好 |
| P1-7 | 语言 | 简体中文；无模板占位符、无 `[PLACEHOLDER]`、无 TODO 残留 |
| P1-8 | 附件与文件名 | 交付清单完整；文件名可读；版本号或日期可区分 |
| P1-9 | 长度与受众匹配 | 给业务方的摘要不堆法条；给法院/仲裁庭的文书论证充分 |
| P1-10 | 交付格式与能力匹配 | DOCX 不保留修订痕迹、批注、脚注或文内图片时，已改为干净副本加复核备忘录，并明确告知用户 |

## 执行步骤

1. 读交付件与案件事实源（`matter.md`、`input/`、证据文件）。
2. 跑引用核验：调用 `legal-citation-check`，把结果附在门禁表后。
3. 逐条填表：`通过` / `不通过` / `不适用（理由）`。不写“基本通过”。
4. 统计：P0 不通过数、P1 不通过数、必须修改项清单。
5. 结论只有两种：
   - **可交付**：P0 全部通过，P1 无阻断性偏差。
   - **不可交付**：列出阻断项、修复动作、需要用户确认的事实。
6. 用户在知情后仍要求交付时，在交付说明中写明未通过项与风险，不删除门禁记录。

## 免责声明

面向个人或非律师用户的对外分析，结尾附：

> 本文件由 AI 辅助生成，供执业参考，不构成正式法律意见。正式意见应由具备相应资质的律师结合完整材料出具。

律师本人使用且交付对象为同行时，可按用户偏好省略声明，但不得声称 AI 结论可直接作为法律意见。

## 记录

门禁结果写入 `matters/<slug>/audit/matter-log.md` 或工作区 `./.legal/audit/quality-gate-<日期>.md`，包含检查时间、交付件路径、阻断项与修复记录。

## Sati 检索接线

- 在本项目中，法条原文优先用 `law_search` 检索（宝宸知识库，含法律层级过滤与现行/失效标注）；引用成稿前用 `law_verify` 逐条做形式核验。
- `law_search` / `law_verify` 不可用或未命中时，如实标注「未检索到 / 未做形式核验」，不得以模型记忆补法条。
