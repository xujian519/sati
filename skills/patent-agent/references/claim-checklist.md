# 权利要求检查清单

> 用于权利要求撰写完成后的逐项质量自查。每个检查项标注其对应的评分维度（清楚性/支持性/必要性/形式规范/保护范围），便于与自动质量预检结果对照。

## 一、清楚性（Clarity）

- [ ] **术语定义明确**：每个技术特征使用所属领域公认术语，无自造词或歧义词
- [ ] **无模糊限定词**：未使用"约"、"大致"、"可能"、"优选"、"例如"等模糊表述
- [ ] **无功能限定过度**：功能性限定的技术特征有结构/步骤支撑
- [ ] **附图标记规范**：附图标记置于技术特征之后的括号内，格式统一
- [ ] **公式/参数明确**：数值范围有明确端点和单位，参数有定义方法
- [ ] **人称/指代清晰**："所述"的引用对象在前文中已出现

## 二、支持性（Support）

- [ ] **上位概念有下位支撑**：权利要求中的上位概念（如"固定件"）在说明书中有至少一个下位实施例（如"螺钉"、"卡扣"）
- [ ] **功能特征有结构支撑**：功能性限定的技术特征在说明书中有对应的结构/方法实施例
- [ ] **数值范围有端点和中间值**：权利要求中的数值范围在说明书中有端点和至少一个中间值的实施例
- [ ] **参数特征有测定方法**：参数限定特征在说明书中有测定/计算方法的记载
- [ ] **材料/组分特征有配比支撑**：材料/组分限定在说明书中有具体配比实施例
- [ ] **优选方案不超范围**：从属权利要求引用的优选方案在说明书中有明确记载

## 三、必要性（Necessity）

- [ ] **独立权利要求包含全部必要技术特征**：独立权利要求记载了解决技术问题的全部必要技术特征
- [ ] **非必要特征已删除**：非必要特征未写入独立权利要求
- [ ] **最接近的现有技术**：独立权利要求的前序部分包含与最接近现有技术共有的必要特征
- [ ] **区别特征在特征部分**：区别于最接近现有技术的技术特征写入"其特征在于"之后的特征部分

## 四、形式规范（Formality）

- [ ] **引用基础正确**：从属权利要求的引用号指向已出现的权利要求
- [ ] **无闭环引用**：无权利要求的引用形成闭环（如 C1 引 C2，C2 引 C1）
- [ ] **多项引多项合规**：多项从属权利要求引用多项（或多引多）符合申请地的专利法规定
- [ ] **权利要求数量合理**：权利要求总数不超过当地专利局的常规数量限制
- [ ] **分句结构规范**：每个权利要求为一个完整的技术方案，使用分句而非逗号串联不同方案
- [ ] **标号连续**：权利要求编号连续，无跳号

## 五、保护范围（Scope）

- [ ] **保护范围合理**：独立权利要求的保护范围与现有技术贡献相匹配，不过宽也不过窄
- [ ] **梯度保护**：从属权利要求逐层增加限定，形成从宽到窄的梯度保护
- [ ] **主题类型适当**：权利要求的主题类型（产品/方法/系统/用途）符合发明实质
- [ ] **备选方案有覆盖**：发明的可预见的替代方案已被权利要求覆盖
- [ ] **方法权利要求有步骤顺序**：方法权利要求按执行顺序记载各步骤
- [ ] **产品权利要求有结构层次**：产品权利要求按组件/部件/子部件的层次记载

## 评分对照

| 维度 | 对应质量预检维度 | 权重 | 通过标准 |
|------|------------------|------|---------|
| 清楚性 | 结构完整性 | 0.25 | ≥ 4/6 通过 |
| 支持性 | 内容充分性 | 0.25 | ≥ 4/6 通过 |
| 必要性 | 结构完整性 | 0.20 | ≥ 3/4 通过 |
| 形式规范 | 引用格式 | 0.15 | ≥ 4/6 通过 |
| 保护范围 | 引用合规性 | 0.15 | ≥ 4/6 通过 |

> 自查完成后，对权利要求文本做自动质量预检（结构完整性 + 内容充分性），再提交人工复核。
