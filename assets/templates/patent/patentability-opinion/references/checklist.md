# 可专利性分析意见 — 自查清单（Checklist）

> 输出 `<artifact>` / 定稿前逐项勾选。P0 必须全部通过，任何一项失败即不得交付。
> 对齐 Open Design `design-templates/ib-pitch-book/references/checklist.md` 的 P0/P1/P2 分层。

## P0 — 必须通过

- [ ] 文书结构完整且顺序正确（页眉 → 抬头 → 案件信息 → 结论摘要 → 依据 → 方案解析 → 逐特征比对 → 创造性 → 其他要件 → 证据清单 → 引用日志 → 假设与局限 → 落款/免责声明/页脚）
- [ ] 结论摘要表覆盖全部授权要件（新颖性 / 创造性 / 客体 / 充分公开 / 清楚支持 / 单一性），每项有结论 + 置信度 + 依据
- [ ] 所有法条引用精确到条款号（《专利法》第22条第2款等），无"相关规定"式模糊表述
- [ ] 每条关键断言在引用日志中有对应行，来源类型与置信度标注正确
- [ ] 无编造数据：公开号、日期、段号、引文均来自真实来源文件；无法验证的内容已标注"假设"并以斜体呈现
- [ ] "容易想到 / 公知常识"类断言已附证据或标注假设
- [ ] 免责声明与密级标识完整（AI 辅助生成声明 + 机密/仅限指定接收人），且抬头所名/密级/免责声明已由品牌契约注入（`--sati-doc-firm/confidential/disclaimer`），非骨架默认值
- [ ] 无占位文案泄漏给用户（骨架中的"________"和"（特征描述）"类占位必须全部替换；保留的说明性括号文字属于模板注释，交付时删除或转为脚注）
- [ ] 对比文件编号规范（首次全称 + 下称 D1，后续统一 D1/D2/D3）
- [ ] 引用日志与正文断言一致（无"正文说已公开、日志说假设"的矛盾）

## P1 — 应当通过

- [ ] 表格数字列使用 tabular 数字（骨架已内置，勿改）
- [ ] 置信度徽标与风险徽标使用约定样式（§5/§6），未引入新色

## P2 — 锦上添花
