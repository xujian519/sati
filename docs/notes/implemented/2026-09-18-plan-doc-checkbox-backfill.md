# Agent Note: 计划文档悬空勾选的批量回收与防复发约定（#359）

Status: implemented

## Problem

`docs/superpowers/plans/*`、`openspec/changes/archive/*/tasks.md`、`docs/*-plan.md` 是任务推进的**历史快照**。任务完成后代码回填了、勾选状态没有——于是这些文档持续把「已交付」写成「未交付」。

代价是可复现的：审计者读到 `- [ ]` 会以为没做，于是每条线索都要走一次「文档说没做 → 去代码核实 → 发现做了」的往返，而且**这份成本随文档数量线性增长**。这不是假设——本仓已多次在补审里撞上它（`TD-WORKSPACE-N04` 的归档 tasks.md、`TD-TEAM-N25` 的 `isCaptainOnline`、`TD-PATENT-N20` 的 P2-4 接线），每次都要重新考古。

2026-09-18 实测规模：**21 份文档、559 处未勾选**（`grep -rc '^- \[ \]'`），其中最极端的形态是——两份 HTML 交付物计划的**产物与文档在同一次提交（`c9dbe6a7` / PR #120）里落地**，勾选却从未回填：计划是「写完就存档」的，从来没人回头对过。

## Decision

**先批量回收，再立约定；判据是「审计者不会再被误导」，而不是「把所有勾选刷成完成」。**

### 1. 逐条核对，三档判定（本 note 的核心口径）

对每处未勾选，去找**它点名的产物**并给出可复核的出处（文件路径 / `文件:行号` / 测试用例 / 提交或 PR 编号），然后落进三档之一：

| 档 | 判据 | 文档里的处置 |
|---|---|---|
| **已交付** | 找到具体产物/出处 | 该行改 `- [x]`，并在「验收状态」段列出 `条目摘要 —— 证据` |
| **仍未交付** | 确实找不到产物 | 保持 `- [ ]`，段里写明现状 |
| **无法核实** | 条目是设计判断 / 里程碑门槛 / 外部依赖 / **一次性运行** | 保持 `- [ ]`，段里写明**为什么无法判定** |

**实测结果（21 份文档 / 559 项）**：

| 档 | 数 | 典型 |
|---|---|---|
| 已交付 | **377** | agent-teams M1–M4 的工具/调度器/面板/角色资产（逐条可指到 `src/**` 与 `tests/**`） |
| 仍未交付 | **37** | `patent-optimization-plan-v2` 的基线保存、SSL 字面 DoD、日志可追溯、兼容性报告；html 交付物的 A4 分页与「无纯白」违规；windows 浏览器自动化的实机项 |
| 无法核实 | **145** | 压倒性是 **TDD 红灯步骤**（"Run test to verify it fails"）与**一次性运行**（typecheck/lint/跑测试/门禁/冒烟）——它们不留持久产物 |

### 2. 每份文档头部留「验收状态」段

```
> **验收状态（2026-09-18 补）**：本文件是历史快照，勾选状态曾长期停留在交付前（见 #359）。
> 截至 2026-09-18 复核：未勾选 N 项中 **M 项已交付**（已回填勾选）、**K 项仍未交付**、**U 项无法核实**。
> - 已交付：… —— 证据 `<文件:行号>` / `<测试路径>` / `<提交>`
> - 仍未交付：… —— 现状
> - 无法核实：… —— 为什么
```

**正文一字不改**：历史快照的价值在于它记的是「当时计划怎么做」，改叙述等于毁掉对照价值。所有更正/差异（实现名不同、方案被 v2 取代、交付后被精简删除）都写在段里。这是采用 `docs/deepseek-harness-phase4-plan.md` §6 已有的正面范式（原文「✅ 全部通过（2026-08-16）——实际验证结果见 §8.3…」）并推广到全部 21 份。

### 3. 立两份防复发约定

- `docs/issue-management.md` **§6.1 计划文档的状态回填**：交付即回填、文件头留验收状态段、整体失效就写「被谁取代」，并明确**这不是门禁**。
- `docs/technical-debt/README.md` **§如何保持新鲜 第 5 条**：把计划文档的勾选纳入"保持新鲜"的清单。

## Alternatives considered

- **把 559 处全部改成 `- [x]`（"完成态收口"）** —— 落选。这正是 issue 警告的**无底洞且无价值**：145 处"无法核实"里绝大多数是 TDD 红灯与一次性运行，翻勾等于伪造证据；37 处确实没做，翻勾等于把真债藏起来。回收的意义恰恰在于**把三者分开**，而不是把数字变小。
- **只做 issue 点名的三条线索**（`broadcast-hub:12`、`m2:1343/1354/1535`、`patent-inventiveness:6/270`）—— 落选。三条线索只是抽样；实测另外 20 份文档里躺着 540 余处同类悬空，只修抽样等于让审计者继续在其余文档上重复往返（issue 的验收标准是"不会再被误导"，不是"抽查通过"）。
- **只加约定、不做批量回收** —— 落选。约定管未来，已存在的 559 处是**存量**；而且正是这批存量给"约定"提供了论据（21 份文档里没有一份是因为"不知道要回填"才没回填，是因为没有任何机制提醒）。
- **给"勾选回填"加一道门禁**（例如交付 PR 必须动过对应 plan 的勾选） —— 落选，且写进了 §6.1：门禁只能看到勾选符号变了没有，看不到"读代码核实"这一步是否发生，做成校验器只会生产形式主义勾选。这与 §7 关闭纪律的立场一致（那里也明确拒绝了"关闭时 body 长度校验"）。
- **删除已失效的历史计划文档** —— 落选。这些文档是**审计线索**：`TD-PATENT-N20` 那类"文档说没做、其实做了"的判定，靠的就是能读当初的计划原文与实现对照。失效的文档改为在文件头写明「被 `…-v2.md` 取代」。
- **把"一次性运行"类条目也判已交付**（口径放宽：测试文件在 + 当期 CI 绿 ⇒ 视为通过）—— 落选。这会让"无法核实"变成 0，但那些条目的**证据在定义上就不可回看**（红灯是交付前的瞬时状态）；如实留白比给一个看起来干净的数字更有用。判据边界在不同作业组之间已尽量统一，个别处（如 phase1 的"全量后端测试"判未交付、nuo 的"门禁"判已交付）松紧不同，已在各自的段里写明理由。

## Consequences

- **换来**：21 份文档从「勾选状态与实况相反」变成**自证状态**——读者在文件头就能看到「这份快照现在处于什么状态、哪些已交付（附证据）、哪些没做、哪些无法判定」，不必逐个考古。**377 项已交付**被回填并附逐项证据（含实现与计划不一致处：实现名不同、被后续 v2 取代、交付后被精简删除）。
- **顺带查出 37 项"确实没做"**——这是回收的副产品，且**有实值**：`patent-optimization-plan-v2` 的 4 项（基线文件不存在、SSL 的**字面** DoD 未满足——`CERT_NONE` 仍在但已改为 `--no-verify-ssl` 显式 opt-in 且默认恢复校验、运行期日志无任务编号前缀、无 Breaking Change 清单）此前被"计划写了 ✅"掩盖；html 交付物的 `pdf` 子命令**实测输出 Letter 而非计划承诺的 A4**（`export-html.mjs` 无 `@page`/page-size 参数）。这些从"看起来做完了"变成"明确列在仍未交付"，是本 issue 最实际的收益。
- **付出**：21 份文档各增 7–23 行「验收状态」段（共 206 行引述块）；**182 处**（37 项仍未交付 + 145 项无法核实）**保持未勾选**——文档的未勾选数并没有清零，若有读者把"未勾选数下降"当成验收指标，会误读这份成果。故每份段里都写了"未勾选**不代表任务未做**"。
- **判据的诚实边界**：三档判定由 6 个作业组分别执行、各自给出证据与不确定项，**没有**机器可校验的一致性；同一类"一次性运行"条目在不同文档里的落档（未交付 vs 无法核实）略有松紧。这层不确定性写在各文档段内，而不是被抹平。
- **仍未处理**：`docs/notes/` 里没有 HTML 交付物特性的决策记录（PR #120 未附 note，属另一件事）；145 项"无法核实"若要真正判定，需要重跑当时的命令——那超出"只读回收"的范围，且多数命令（TDD 红灯）在事后**原理上**不可重放。
