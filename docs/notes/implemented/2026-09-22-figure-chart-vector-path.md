# Agent Note: 图型扩展第二批（曲线图 / 坐标图，矢量通路）

Status: implemented

## Problem

第一批（状态图/层级图）走的是 DOT 通路——图型扩展分批的原话是「DOT 通路先（状态图/层级图，复用
`dot.ts`）→ 矢量通路后（电路/曲线/剖视/时序）」。矢量通路这一批里，**曲线图是中文实务出现频率最高、
缺口最大的一类**：性能/实验数据的附图（温度—转化率、时间—强度、浓度—吸光度）在化学、材料、机械
领域几乎是标准配置，而当时的 FigureSpec 只能表达"节点 + 边"，画不出坐标轴与数据曲线：

- 用 `block` 硬套：节点当数据点、边当连线，得到的是折线图**没有坐标轴、刻度与单位**，读者读不出数值；
- 走 Graphviz：DOT 语言本身没有坐标轴与数据序列概念（`pos` 只能钉死像素坐标，等于把布局外包给模型）。

对照实现 `deepseek-harness` 有 `plot-diagram.ts`（412 行，毫米坐标系的自绘曲线图）与 `vector-figure.ts`
（矢量通路接缝：`VectorFigureSpec` = 画布毫米 + SVG 片段 + 图面词语）。本条按 Sati 的既有契约落地
同一件事，但不引入第二条接缝。

## Decision

`FigureKind` 增 `"chart"`；`FigureSpec` 增**可选** `chart` 载荷（`x`/`y` 轴 + `series` 数据序列）——
`nodes`/`edges` 保持必填（曲线图传 `[]`），既有图型与全部消费方（sidecar/check/brief/html/readback）
零改动即可容纳新图型。新增 `src/patent/figuregen/chart.ts`（布局 + 自绘 + 图面词语 + 样式冲突，
与 `layout.ts` 平行的第二条通路），`render-svg.ts` 按 kind 分流，**图号仍由 `render-svg.ts` 统一加在
图形正下方**（4.3），曲线图模块只管图形。

| 决策点 | 结论 | 理由 |
|---|---|---|
| 载荷落点 | `FigureSpec.chart`（可选字段），不是独立工具 | sidecar/核验/门禁全部按 FigureSpec 契约工作，另立工具要再造一条链；`direction`/`abstract`/`figure_no` 复用 |
| 单位 | px（与其余图型同源） | 纸面毫米由 `page-contract.ts` 的统一缩放换算；V7 的打印字高判据对曲线图因此照样成立（若像 DSH 那样直接画毫米，V7 就得为这一类图另写一套） |
| 刻度算法 | 步长取整（1/2/2.5/5 × 10^n），**范围与刻度由同一条步长决定** | 曾先取整范围、再等距分割刻度，得到 1/1.75/2.5/3.25/4 这类非整档标签（视觉验证发现）；两者同源后数据 0..96 配 5 个刻度即 0/25/50/75/100 |
| 自动范围是否外扩 | **不按百分比外扩**，只向外取整 | 5% 外扩会把"时间 0..4h"推成 -2..6h（含负值、超量的轴），读数反而失真；取整本身已让数据一般不贴住轴线 |
| 显式 min/max | 显式端**原样固定**，另一端仍取整 | 调用方给 `min: 0` 是取舍（曲线从 0 起），工具不得改写；但缺省端不取整又会得到 0/24.25/… 这类标签 |
| 多序列区分 | 未指定 `marker` 的序列按固定顺序自动分配不同标记（实心→空心） | 黑白附图不得用颜色，标记与线型是唯二区分手段；自动分配保证"不写样式也可用" |
| 图例位置 | 横轴标目下方折行列出（DSH 同） | 不侵犯数据区（图内左上角图例在数据密集时必被压盖）；有 `name` 才画，`legend: false` 可关 |
| Graphviz 通路 | **fail-loud**（`buildFigureDot` 抛错 + 工具层落盘前预检） | 坐标轴与数据曲线不是图论结构，静默出一张空图会让"要 graphviz 布局"的意图变成一张错图 |
| 新规则 | V19（实用新型附图全为曲线图，warn）、V20（曲线无从分辨）、V21（数据点超出坐标轴范围） | V19 有条款依据（细则 20.5）；V20/V21 是渲染契约缺陷（与 V18 同类，**不引条文**） |
| 是否补 `data-figure-kind` 根属性 | 不补 | 回读通路只观测图号与标记；曲线图的 V19/V20/V21 本就依赖结构化载荷（同 V2/V3 依赖说明书文本），补属性是为一条用不上的观测面改全部快照 |
| 对数坐标/误差棒/双纵轴 | 不做 | 未在需求内；对数刻度要另一套取整与标签算法，等有真实用例再单独立项 |

**V19 的依据与边界**：细则第二十条第五款「实用新型专利申请说明书应当有表示要求保护的产品的形状、
构造或者其结合的附图」（本机知识库的细则全文已核）。触发条件收窄为「**cn + utility + 全部附图都是
曲线图 + 看全本案**」，级别 warn、措辞是"请确认另有结构视图"——因为结构视图可能由 CAD 通路单独产出
（不进 `figures` 数组），分次核验时也无从判断。⚠️ DSH 的 `plot-diagram.ts` 把这条引作「指南一部二章
7.3(10)」，但在可核验的来源里找不到该条号，故**不引**（照抄未核验的条号比不引更糟）。

**inputSchema 变更 → fixture 重录**：`FIGURE_INPUT_SCHEMA_REF` 增 `chart` 属性、`kind` 枚举增 `chart`，
请求键（含 toolSchemaDigest）必然失配，随本批重录 `tests/fixtures/llm-replay/deepseek-v4-flash-basic/`；
重录须显式 `PILOT_AGENT_MODEL=deepseek/deepseek-v4-flash`（本机 `~/.sati/sati.yaml` 的 agent.model 与
fixture 不一致时，模型名不同即请求键不同——第一批已踩过）。

## Alternatives considered

1. **沿用节点/边画曲线**（数据点当节点、连线当边）：坐标轴、刻度、单位、图例全都表达不了，
   得到的只是"带折线的框图"——与要解决的问题正相反，否决。
2. **给 Graphviz 传 `pos` 钉死坐标**：等于把布局与坐标换算外包给模型，确定性与合规扫描一并失守；
   且 DOT 的 `pos` 需要 `-Kneato -n` 之类开关，渲染器分支会翻倍，否决。
3. **引入 DSH 的 `vector-figure.ts` 第二接缝（毫米画布 + 片段 + labels）**：Sati 已有 `FigureSpec`
   作为唯一契约，再立一条接缝会让 sidecar/核验/门禁都要判"这幅图走哪条链"；直接在既有契约上加载荷，
   消费方零改动，否决。
4. **另立 `patent_figure_plot` 工具**：多一个工具就多一份 schema 与重录面、多一处事件矩阵与文档，
   而曲线图与其余图型共用 figure_no/摘要附图/图号/落版/门禁；并入既有工具更省，否决。
5. **自动范围按数据外扩 5%（DSH 做法）**：视觉验证里"时间 0..4h"被推成 -2..6h，负时间轴是明确的
   读数错误；改为只向外取整，否决外扩。
6. **刻度一律等距分割两端点（DSH 做法）**：范围内端点精确，但标签常出现 24.25/48.5 这类非整档值；
   专利附图是给人读的读数载体，取整改为"步长优先"，接受"实际刻度数与目标值可能不同"，否决等距分割。
7. **未指定样式时一律默认同一标记（DSH 默认全 `circle`）**：两条同标记同线型的曲线在黑白图面上
   完全重合，属静默失真；改为自动分配不同标记 + V20 报显式重复，否决统一默认。
8. **把超范围数据裁剪到绘图区（clamp）**：裁剪会把"超出量程"画成"贴着上边界"，是比难看更坏的失真；
   改为报告 V21 且不裁剪，让调用方改范围或数据，否决裁剪。
9. **曲线图也支持 `direction: LR`**：坐标轴是约定的读法（横轴在下、纵轴在左），换向没有对应实务
   惯例；`direction` 对 `chart` 明确忽略，否决。
10. **引入类目轴（x 为离散标签）**：专利曲线图的横轴绝大多数是数量轴；类目轴要另一套刻度与折行算法，
    没有用例支撑，未做。

## Consequences

- `FigureSpec` 契约扩展（新增可选 `chart` + `kind` 增 `chart`）：新增图型不改既有图型的渲染与快照
  （`render-svg.ts` 只多一条分支，`layoutFigure` 完全不动）；但**改 `inputSchema` 即须重录 fixture**，
  本批已重录。
- 核验规则增至 V1–V5、V7–V21。**V18/V20/V21 的依据是渲染契约而非条文**，规则底座里逐行标注，
  不伪装成法条。
- 曲线图**只能走内置渲染器**：`SATI_FIGURE_RENDERER=graphviz|graphviz-wasm` 时工具在落盘前报错
  （不留半成品目录）。这是「渲染器可选」这条设计的第一个例外，已在 SKILL 与规则底座写明。
- V19/V20/V21 需要**结构化载荷**（`figures` 入参或 sidecar）：`svg_paths` 回读只观测图号与标记，
  拿不到序列与范围 ⇒ 那三个规则在回读通路不生效（与 V2/V3 需要说明书文本同理，如实声明）。
- 入参结构性校验（空 `nodes` / 空 `series` / 畸形数据点 / 缺轴标目）从 generate 扩到
  `patent_figure_check`，两工具共用 `assertFigurePayloads`：此前 check 会静默接受"空节点图"并给出
  一份看不到缺陷的报告；回读通路（`svg_paths` 骨架无 nodes/chart 载荷）不套这套约束，避免误伤。
- 曲线图的对数坐标、误差棒、双纵轴、类目轴未做；其余矢量图型（电路/剖视/时序）仍未开工。
