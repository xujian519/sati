# Agent Note: 桌面端退出前确认（常驻应用的退出代价）

Status: implemented

## Problem

正念智能体是常驻应用：关主窗口只是隐藏，本地服务（gateway / server 子进程）与后台任务继续跑。但"退出"是**立即**停掉这一切——用户按 Cmd+Q 或点托盘"退出"时，正在跑的检索/撰写任务会被中断，而此前没有任何提示。对"随手关一下"的心理预期，代价并不对等。

## Decision

`before-quit` 增加确认闸门：用户主动退出时弹一次原生确认框（默认按钮是"取消"），确认后才开始 shutdown；托盘"退出"、Cmd+Q、"文件 > 退出"共用同一条链路。程序化退出（启动失败、无托盘平台的关窗兜底）显式跳过确认。

判定表与两种语言的文案抽到 `apps/desktop/src/quit-confirm.ts`，让判定与接线分离：

- 关停已开始 / 确认框已开着 → 忽略（连按 Cmd+Q 不叠框，也不在 kill 子进程中途退出留孤儿）；
- 已确认 / 程序化退出 → 直接关停；
- 否则 → 先确认。

托盘"退出"不再预设 `isQuitting`，交给同一闸门；`isQuitting` 只在真正开始关停时置位（窗口 close 处理器与 renderer 自愈都读它）。确认框绑主窗口作父级，避免落到窗口后面。

## Alternatives considered

- **只在"有后台任务在跑"时确认** — 落选：主进程要为此查询本地服务的任务状态，多一条跨进程依赖与失败路径；而"退出会停掉常驻服务"与有没有任务无关，是每次退出都成立的事实。
- **不确认，只在退出后提示** — 落选：提示无法阻止误触，退出已经发生。
- **托盘"退出"免确认（当作明确意图）** — 落选：托盘菜单是右键误点的常见位置，"退出"正与"显示主窗口"相邻，恰恰最需要确认。
- **判定逻辑留在 `main.ts` 内联** — 落选：Electron 主进程没有可用的测试基建（L2 冒烟需要打包好的 `.app`），内联即零覆盖；拆成纯函数后判定表与文案都能直测，接线只剩一处调用点。
- **无托盘平台也确认** — 落选：那条路径上窗口已销毁、没有可恢复的界面，取消会把用户留在"看不见又退不出"的状态。

## Consequences

- 主动退出多一次确认；取消后服务与任务继续，界面可由 Dock（macOS）或托盘（Windows）恢复。
- 程序化退出不受影响：配置不可用导致的启动失败设 `skipQuitConfirmation`；启动期严重失败走 `app.exit`（本就不经过 `before-quit`）；单实例锁未拿到的退出发生在注册 `before-quit` 监听之前。
- 判定表与 zh/en 文案有 7 条直测（含"忽略/关停/确认"三态与默认键为取消）。
- **真正的 Electron 接线（`before-quit` / 托盘菜单 / 原生对话框）未在运行中的桌面端验证**：那需要打包 `.app` 后驱动原生对话框，仓库既有的入口是 `apps/desktop/scripts/release-l2*.sh`。
- 新增 `apps/desktop/src/quit-confirm.ts` 与 `tests/desktop/quit-confirm.spec.ts`。
