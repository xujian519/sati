# 专利附图：CAD 结构图的剖视图（剖面线）与附图标记标注

Status: implemented（2026-09-17）
Scope: `src/patent/figuregen/cad/`（types/freecad/render-cad/checks）、`src/tool/builtin/patentFigureProject.ts`、`src/patent/figuregen/sidecar.ts`、`scripts/record-cad-fixtures.ts`、`tests/fixtures/patent/cad/`

## Problem

CAD 结构图（阶段一：已有 STEP 源 → 无头投影）落地后仍有两处**交付能力空缺**，都是"图能出但不能用"：

1. **内部结构表达不了**：只出整视图，要看内部只能开隐藏线（虚线）。CNIPA 实务以**剖视图**表达内部结构，且指南一部一章 4.3 明示虚线不得妨碍附图标记线。实测 `CAD_VIEWS` 只有前后左右上下与轴测七个方向，无剖切语义。
2. **投影图没有附图标记**：`patentFigureProject` 落盘的 sidecar 里 `spec.nodes` 是空骨架，图上没有任何标号 ⇒ 代理师必须手工补标号，且附图门在定稿期跑 V2（图内标记须在说明书文字部分出现）时对该路径**空转通过**——"合规"是真空的。

根因是契约层缺一块：边表 v1 只有**模型三轴的像**（`axes.x/y/z`），没有**原点的像**。三轴像各自含同一个未知平移 `t`，仅凭它们定不出模型坐标 → 图面的仿射映射；没有这个映射，既无法把调用方给的标记锚点投到图上，也无法把剖切面轮廓交回 Sati 侧投影。

## Decision

| 项 | 决策 |
|---|---|
| 剖切方式 | **全剖视图**：`section_offset_mm` 给出剖切面沿视线方向的带符号位置（模型坐标），剖切面垂直于视图方向，保留**远离观者**的一侧（`p·d ≤ offset`），经半空间 `common()` 得到剖切后的实体。只允许轴对齐视图（`CAD_SECTION_VIEWS`，轴测图无剖切面语义 ⇒ 入参与脚本生成双重 fail-loud） |
| 剖切面轮廓 | 以**模型坐标**多环输出（外环 + 孔/缺口内环），投影由 Sati 侧 `projectModelPoints` 完成——**投影实现只有一份**（Python 侧不重复实现朝向对齐） |
| 剖面线 | 45° 细实线（0.2mm），**纸面**等间距 2.5mm，扫描线 + 奇偶规则填充（多环自动留空），先于轮廓绘制；输出为单条 `<path>` 段序列（确定性、可审计）。间距取纸面毫米 ⇒ 缩放后疏密观感不变 |
| 环的拼接 | `wire.OrderedEdges` **不可信**（实测剖切面边序乱序：顶边→左边→圆弧→底边→右边）。改为按端点做连通性搜索逐边拼接 + 必要时反转，并在脚本与解析器**两侧**校验闭合性（不闭合即 fail-loud，拒绝输出会画错的剖面线） |
| 附图标记锚点 | 模型坐标（毫米，`at_mm: [x,y,z]`）——调用方本来就知道自己的模型坐标；由 `axes.origin` 与三轴像定出的仿射映射投影到图面，再作为引线起点 |
| 标号落位 | 缺省"向图外引"（方向 = 锚点相对图心），引线止于标号外缘 1.5mm；可经 `label_offset_mm` 显式指定（纸面毫米，绝对值上限 50mm） |
| 图幅 | 有标注时四边各预留"最长引线 + 半个最宽标号 + 余量"的**标注带**，几何按剩余可用宽度缩放 ⇒ 含标注的纸面尺寸**由构造保证**不超 A4 可印区（无标注时预留带为 0，图幅与旧行为逐位一致） |
| 标记与回读 | 每个标号渲染为 `<g id="n-ref-<标记>" data-ref="<标记>">`（引线 + 文本）——与内置渲染器的回读契约同构，`patent_figure_check` 的 `svg_paths` 通道可直接复核 CAD 图 |
| 定稿期核验 | sidecar 的 `spec.nodes` 由标注生成（`id: ref-<n>`、`label: <标号>`、`ref`）⇒ 附图门的 V2/V4 在 CAD 路径上**真正生效**（实测：漏标号即 V2 fail 并挂 HITL） |
| 规则 | 新增 C5 剖切有效性（请求剖切但无剖切面 ⇒ fail）、C6 剖面线可辨性（有剖切面但一条线也画不出 ⇒ warn）、C7 标注重叠（warn）、C8 锚点落在投影几何范围外（warn）、C9 标号越出图幅（fail） |
| 契约版本 | 边表 v1 → **v2**：`axes.origin`（必需）、`section`/`cutFaces`（剖切时成对出现）。解析器拒收 v1（缺原点像 ⇒ 映射不可定），并校验 `section` 与 `cutFaces` 必须成对、环必须闭合 |
| fixture | 新增 `scripts/record-cad-fixtures.ts`：试件几何（40×30×10 平板 + 沿 Z 的半圆槽）与视图清单都写进脚本，用真实 FreeCAD 重录 front/iso/剖视三个边表 ⇒ fixture **可复现**（此前只记录了结论、没记录试件构造） |

## Alternatives considered

- **用 FreeCAD 的 `projectToSVG` 出剖视图（连它的剖面线一起用）** — 落选：那是第二套交付契约（颜色/线宽/版式/`data-ref` 都要重新归一化，实测其默认样式 `rgb(0,0,0)` 会被本模块的黑白不变式判非黑白）。剖切只借它的布尔与投影能力，画仍由本模块契约负责。
- **用虚线（隐藏线）代理"表达内部结构"** — 落选：虚线不是剖视图，CNIPA 实务以剖视图表达内部结构，且 C4 已明示虚线易与标记线混淆。
- **剖面线用 SVG `<pattern>` 填充剖切面** — 落选：交付契约只允许 `#000000`/`#FFFFFF` 且无渐变；pattern 的 `patternUnits`/用户单位换算在不同渲染器上不一致（PDF/浏览器/栅格器），且回读与审计看不到几何。改为确定性扫描线 + 显式线段。
- **剖切面轮廓在 FreeCAD 侧投影后输出 (u,v)** — 落选：投影实现会出现两份（Python 与 TS），朝向对齐必然漂移；模型坐标 + 单点投影实现更稳。
- **按 `wire.OrderedEdges` 直接拼接环** — 落选（实测踩中）：边序是乱序，拼接留下一条 50mm 的跨图假闭合边，剖面线画到剖切面之外（首版渲染即为此），回路长度 222mm 而非 142.8mm。改为连通性搜索 + 闭合性校验。
- **标注锚点用图面二维坐标（调用方指定）** — 落选：调用方拿不到投影坐标系（`(u,v)` 是 TechDraw 的内部约定），等于把内部细节推给使用方。模型坐标是调用方本来就掌握的信息。
- **标号自动避让（迭代放置/最优化）** — 落选（本次不做）：本模块的纪律是"确定性 + 可审计"，自动避让属启发式且不可复现。改为"缺省向图外引 + 显式 `label_offset_mm` + C7 重叠检测"（重叠只是告警，人工/模型可一次性改过来）。
- **把"剖面线越界"做成运行时规则（C10）** — 落选：闭合环 + 扫描线填充下，越界只可能来自**自交环**，而"环是否自交"没有便宜且确定的判定。改为解析期闭合性 fail-loud + 单测属性断言（剖面线中点必须全部落在剖切面内、缺口内不得有剖面线）。
- **剖切面轮廓作为独立工具暴露给模型** — 落选：剖切是投影的**参数**而非新能力，独立工具会让模型多一次调用且步调可错（先投影后剖切即不一致）。

## Consequences

- **边表 v1 → v2**：`axes.origin` 成为必需字段。旧 v1 边表（含此前的 fixture）被解析器拒收，理由写进错误信息（缺原点像 ⇒ 仿射映射不可定）。fixture 用真实 FreeCAD 重录：**front 视图逐点一致**（同一零件、同一投影契约），iso 视图的**边切分**与旧记录不同（旧记录的试件构造方式未入库、不可复现），剖视图为新增；试件定义现已随录制脚本入库，此后可复现。
- **工具 `inputSchema` 变更**（新增 `section_offset_mm` 与 `annotations`）⇒ 按方案 §7 手册重录 `tests/fixtures/llm-replay/deepseek-v4-flash-basic/`（与本次改动同批）。
- **sidecar 增字段**（`geometry.section`、`geometry.ref_numerals`）：与既有的 `geometry.findings` 一样是可选附加字段，sidecar 结构版本不变（解析器只校验消费所需的最小结构）。
- **能力边界（诚实声明，未做）**：只做全剖视图——旋转剖/阶梯剖/局部剖不做；剖面线间距固定 2.5mm（不按剖切面尺寸自适应，过小的面由 C6 告警而非自动加密）；不检测"锚点落在空材料处"（剖切缺口内的锚点仍会画，C8 只判"是否落在图内几何范围"）；剖面线不与引线/标号做避让；投影法（第一角/第三角）的纸面配置仍不声称遵循。
