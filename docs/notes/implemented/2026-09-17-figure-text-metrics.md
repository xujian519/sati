# Agent Note: 附图盒宽按字符类别度量（CJK 1em / Latin 0.5em）

Status: implemented

## Problem

布局器用**单一字宽常数**估宽（`CHAR_W = 15`，且对每个字符一视同仁）：
`nodeSize` 取 `longest * CHAR_W`。CJK 与 Latin 的实际字宽相差近一倍，于是同一常数
必然在其中一侧失真：

| 标签 | 字符数 | 旧盒宽 | 实际渲染宽度 |
|---|---|---|---|
| `处理模块` | 6（CJK） | 122px | ≈ 84px（尚可） |
| `Data processing module` | 22（Latin） | **362px** | ≈ 154px（**约 2.4 倍**） |

后果不止"盒子偏大"：画布尺寸被推高后进入 V7 的纸面判定，英文标签图会因虚胖画布而
被误判超页/字高不足——即度量失真会污染合规判据。

## Decision

新增 `figuregen/metrics.ts`（字号 + 字符类别度量）并让布局器改用它：

- `measureTextWidth(text, fontSize)`：按码点区间判宽字符（CJK 汉字/假名/谚文/全角标点与
  全角形式），宽字符 1em、其余 0.5em；`FIGURE_FONT_SIZE = 14` 与渲染的 `font-size` 同源。
- `nodeSize` 取「各行 `measureTextWidth` 的最大值」+ 内边距，`MIN_W` 下限不变。
- 字号常量移到 `metrics.ts`：布局器（盒宽）与渲染器（font-size）都要它，放任一侧都会让
  两者互相 import 成环；`check.ts` 的打印字高判据也从这里取字号而非从渲染器取。

仍然**不读字体文件、不做 canvas 测量**——度量是纯函数，确定性不受平台/字体影响。

## Alternatives considered

- **引入字体度量库 / 读系统字体文件（如 opentype.js + 打包字体）** — 落选：渲染器刻意零
  外部资产（构建体积、跨平台确定性、离线可用），而此处只需"盒子别虚胖一个数量级"的精度；
  真实字宽换来的是亚像素级准确，代价是新增资产依赖与两条构建路径的分叉。
- **按字符类别查表（大写/小写/数字各不同系数）** — 落选（本次不做）：ASCII 内进一步细分
  只能收敛几像素，却让度量表变成需要与某款字体对齐的知识；等出现"盒子明显不齐"的实测
  案例再引入。
- **只把 `CHAR_W` 调小（如 8）以求平均误差最小** — 落选：那会让 CJK 标签反过来**偏窄**
  （盒子装不下文字），用一个普遍存在的错换掉一个方向明确的错；分类度量才是两侧都对的解。
- **同时改行高（`LINE_H`）与内边距以"顺带统一度量"** — 落选：行高/内边距当前无实测缺陷，
  改动会把本笔记的结论（字宽分类）与无关的版式调整混在一起，且直接改变所有既有图的观感。

## Consequences

**换来**：英文/中英混排标签的盒子不再虚胖约 2.4 倍，画布尺寸与文字实际占位一致；
V7 的纸面尺寸判定不再被虚胖画布推高（英文标签图的误报减少）。

**付出**：

- **所有附图渲染输出发生变化**（盒宽、画布宽高、`viewBox`），既有 SVG 交付物与新生成
  结果不一致——对本模块的**输出确定性**无影响（同输入仍逐字节一致），但它属于可见的
  版式变更，需要重出已交付附图。
- CJK 单字宽由 15px 变 14px（−6.7%）：中文标签盒子略窄，属预期修正。
- 宽字符区间是**启发式集合**（覆盖 CJK/假名/谚文/全角形式），非 Unicode East Asian Width
  全表；emoji 等按半角计。若将来出现西里尔/阿拉伯等宽字符场景需扩表。
