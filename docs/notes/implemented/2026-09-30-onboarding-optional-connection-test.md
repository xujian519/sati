# Agent Note: onboarding 的连接测试改为可选

Status: implemented

## Problem

LLM 配置步骤把"连接测试通过"当作保存的准入门槛（`disabled={testStatus !== "success"}`），旁边写着"请先测试连接。"。对非技术向用户这是两道坎：测试会真的打网络，可能因代理、额度或端点差异失败，失败后按钮永久禁用——字段明明填对了也走不下去；而"先测试连接"这句话在真正缺字段（没填密钥）时又是误导，那时真正的原因是字段没齐。

## Decision

保存按钮的启用条件从"测试通过"改为**表单齐备**：provider、端点、凭证（该 provider 需要时）、至少一个模型。连接测试保留为诊断按钮（同样以表单齐备为前提），不再决定能否保存。

提示文案改为"连接测试可选，可直接保存并继续。"，只在「表单齐备且状态为未测试」时显示——避免与测试中/测试失败/测试成功的反馈叠在一起。改输入即复位测试状态的行为原本就有（多处 `setTestStatus("idle")`），未改动。

## Alternatives considered

- **保留门槛，另加"跳过测试"入口** — 落选：同一个按钮上叠两种语义，用户仍要先理解"测试"这件事；直接以表单齐备为准更简单。
- **保存时自动先跑一次连接测试** — 落选：把网络往返与失败分支塞进保存路径，保存会因上游抖动而失败；测试的价值是"提前指出哪个字段不对"，不该成为保存前提。
- **只在测试失败后放开按钮** — 落选：仍要求用户先经历一次失败，且"测试通过才能存"的假设没变。
- **保留"请先测试连接"文案** — 落选：语义已反转，留着会让人以为必须测试。
- **保留 `testConnectionFirst` 文案键** — 落选：随语义反转成为死键，双 locale 与 i18n 键清单同步移除。

## Consequences

- 未做连接测试即可保存并完成引导。浏览器实测（独立 `SATI_CONFIG_PATH`，未触碰真实配置）：填入密钥 → 保存按钮由禁用变可用、提示出现 → 点击保存后离开引导页进入主界面，配置正常落盘。
- 连接测试仍可用；改任何输入都会把它的结果复位。
- 移除死键 `llmSetup.testConnectionFirst`（en / zh-CN 与 i18n 键清单）。
- 上游 #614 的其余部分（逐模型探测文本/图片能力、`useLlmSetup` hook 与 `ConnectionStep` 重组、`routes/onboarding.js`）未移植：Sati 的 onboarding 组件形态不同，这里只取"测试不是门槛"的语义。
