# Agent Note: C21/C22 日卡 P0 候选修复批次

Status: implemented

## Problem

C21/C22 日卡审阅登记了 8 个 P0 候选（详见 `docs/code-refinement-plan.md` C21/C22 记录）。保守档精炼卡只登记不修，因为每一项的修复都改变现有行为，且核心模块改动必须附测试。其中两项会在长生命周期进程里必然恶化：`BackgroundTaskRuntime` 的任务注册表永不清理（累计启动 32 次后 `start()` 永久抛错）；`CronManager.ensureRuntime` 启动失败后僵尸 runtime 残留注册表（后续调用永不重试，定时任务静默不触发）。

## Decision

按影响排序逐项修复，每项独立提交并附测试（fix 卡批次，同一 PR）：

1. **BTR 注册表**：`maxTasks` 只统计未结束（`endedAt === undefined`）的任务；终态 entry 按 `finishedTaskTtlMs`（默认 1h，0 = 永不清理）在 `start()`/`list()` 惰性清扫。
2. **CronManager 回滚**：`ensureRuntime` 中 `writeProjectMarker`/`runtime.start()` 失败时把 runtime 移出 `runtimes`/`starting` 并 best-effort `stop()`，下次调用重建重试。
3. **memory 平铺 schedule 字段**：`memory.schedule` 段存在且平铺字段也会被消费时，发 `CONFIG_MEMORY_FLAT_SCHEDULE_FIELDS_IGNORED` warning；schedule 段优先的既有语义不变。
4. **TaskOutputStore.readSlice**：字节切片在 UTF-8 码点边界收尾——尾部不完整序列回退 `nextOffset` 留待下轮重读（不丢数据）；头部孤立 continuation 字节跳过不再产出 U+FFFD。
5. **FileHistoryStore.safeReadText**：非 ENOENT 读取失败经 `options.warn` 告警后仍按 null 处理（diff stats 的 fail-safe 语义不变，但从静默误判变为可审计）。
6. **TranscriptReader legacy 缓存**：缓存命中返回的 `diagnostics` 也拷贝，与 entries 一致、与 tail 路径对齐。
7. **CronRuntime.runTaskNow**：孵化一次性任务的 `runAt` 改用注入时钟 `this.now()`；每次 run-now 孵立独立一次性任务、触发后自删的语义保留（见 Alternatives）。
8. **SessionMetadataStore.saveAiTitle**：删除两分支逐字相同的死条件，JSDoc 写明覆盖保护由调用方负责（TurnRunner 两处调用已实现 first-write-wins 检查）。

## Alternatives considered

- **BTR：完成即删 entry** — 落选：UI 依赖 `list()`/`getOutput()` 在任务完成后查看历史与输出，立即删除破坏任务历史视图；TTL 保近期可见且内存有界。
- **BTR：定时器周期清扫** — 落选：需要管理 timer 生命周期与 unref；`start()` 是泄漏的驱动源，惰性清扫即可，实现更简单。
- **CronManager：existing 分支内重试 start** — 落选：把失败恢复散进读路径，且无法区分"已启动"与"启动失败"；回滚注册表让失败不可观测地消失才是正解，重试语义自然成立。
- **memory 平铺字段与 schedule 段合并生效** — 落选：改变现有配置的实际行为（已有配置可能依赖 schedule 段优先），静默变更风险大；告警让冲突可见，合并语义留产品决策。
- **readSlice 用 StringDecoder 维持跨调用解码状态** — 落选：readSlice 是按任意 offset 的随机访问接口，有状态解码器在多调用方/乱序轮询下错误累积；无状态边界对齐保持接口纯函数语义。
- **safeReadText 非 ENOENT 改为抛错** — 落选：单个不可读文件会炸掉整个 diff 视图；warn-and-continue 与 evictIfNeeded 的既有 fail-safe 模式一致。
- **saveAiTitle 在 store 内实现覆盖保护** — 落选：调用方已实现该检查，store 内再加一层是冗余防御且改变公共方法语义（显式覆盖场景被误伤）。
- **runTaskNow 去重待触发的 run-now 任务** — 落选（本轮）：孵化-自删语义下"累积"是瞬态的且每次点击即一次立即执行，可解释为设计；去重需要跨任务标记，属产品语义变更，留独立决策。

## Consequences

长生命周期 gateway 不再因后台任务累计启动而永久不可用，cron 单次启动故障可自动恢复；配置冲突、读取失败从静默变为有诊断/告警。付出的代价：`maxTasks` 语义收窄为"并发上限"（错误文案同步更新）；终态任务 1 小时后从列表消失（可配置）；UTF-8 边界对齐使 `nextOffset` 在多字节字符中部时回退（字节零丢失，但单次切片内容变短）；新增一种配置 warning code。
