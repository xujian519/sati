# Agent Note: 附图多视图的「A4 拼版页」——多张视图共用一页的统一缩放版式

Status: implemented

## Problem

批次 C 之后，CAD 通路一次可产出多视图（`SATI_CAD_VIEWS=front,top,right`）：每视图一张 SVG +
一份 `<name>-fig<N>-manifest.json`。但**整页 A4 版式只有主视图有**——`submission-page.ts` 落的
是"一幅图占一页"，于是多视图交付缺"一整页"这个形态：

- 把主视图的落版页当作多视图交付的整页版式 ⇒ 交出去的一页只含 1/N 的信息；
- 把各视图各自缩放后塞进一页 ⇒ 同页各图字高不一致，而"缩小到三分之二仍可辨"
  （指南一部一章 4.3 / PCT Rule 11.13(c) / 37 CFR 1.84(k)）对同一页的各图是**同一个**判据；
- 把各视图按**整页版心**算缩放再塞进小格子 ⇒ 图形撑出格子，且字高被高估（判据与实际排版漂移）。

批次 C 的决策记录把这一项明确列为"未做（版式问题，不是投影问题）"。本条补上它。

## Decision

### 一、新增 `figuregen/submission-sheet.ts`：多张视图 → 同一张 A4

拼版页是**附加**产物（`<name>-fig<N>-sheet.svg`），与既有的单图落版页（`-page.svg`）并存、
互不覆盖。

**排布规则**（择优顺序即规则本身，写死在模块里便于复核）：

1. 候选列数 C = 1…N，行数 R = ⌈N/C⌉；视图按**阅读序**（自左至右、自上而下）落格，末行不满时
   左对齐留空；
2. 格宽 = (版心宽 − (C−1)×格间距)/C；格高 = (版心高 − (R−1)×格间距 − 页码带 − 图号带)/R；
3. 择优：**统一缩放系数最大** → 格形更接近方形 → 列数更少；
4. 所有格共用**同一个**缩放系数（`uniformFigureZoom` 口径，恒 ≤ 1：不放大），且系数按
   **拼版后的单格可用区**算，不是按整页版心算；
5. 逐格在自己的格内居中；图号落在格底（图号带），页码落在版心底。

**为什么按这个顺序择优**：附图页的第一判据是"缩小到三分之二仍可辨"，即**字高**；网格形状只是
手段。故先最大化统一缩放系数（= 字高），同分再谈形状（接近方形 ⇒ 图形在格子里不浪费边），再
同分取列数更少（格更大 ⇒ 单个视图更好读）。实测：3 张大图时 2 列 × 2 行的单格宽高比 1 列 × 3 行
大一截 ⇒ 系数更大 ⇒ 选 2 列。

### 二、编号规则仍由法域档案决定，本模块不解释

- **图号**由**调用方**经 `figureCaption` 取得后按格传入（CAD 视图的图号已由渲染器画在图面
  下沿 ⇒ 该通路不重复传，避免一页两个图号）；
- **页码**由本模块经 `sheetNumberText` 取得（调用档案函数，不自己拼字符串）。

两处各解释一次必然漂移 ⇒ 本模块只"取用"档案结论。

### 三、字高核验：不合规**如实报出**

拼版后字高 = 源字高 × 统一缩放系数。低于 `minCharHeight(profile)` 时：进 `warnings`、进工具
报告行、进 sidecar 的 `char_height_compliant=false`，并给可照做的建议（减少同页视图数 / 改用
单幅落版页）。消息取合规核算模块 `compliance.ts` 的同一条口径（同一判据不两处措辞）。
另核图号字号本身也不低于法域下限。

### 四、产物接线：单视图零变化

- 多视图 + `fit_to_page` ⇒ 额外落拼版页；
- **单视图走既有单图落版页，默认路径零变化**（逐字节不变，见 Verification）。

### 五、sidecar：`layout` 语义不动，另立新字段

`layout` 仍是"一幅图落版的纸面度量"（单图口径）；拼版页的度量是"多格共页"（几列几行、每格
多大、所有格共用的缩放系数、字高是否达标）⇒ 另立可选字段 `sheet_layout`。旧 sidecar 无此字段
仍合法（不升 sidecar 版本）。交付物清单里拼版页登记为 `submission-page` 角色。

## Alternatives considered

- **多视图时用拼版页「取代」主视图落版页** —— 否决：`layout` 字段的语义是"一幅图落版的纸面度量"，
  取代后同一字段在不同模式下含义不同（下游只能靠猜哪个是哪个）⇒ 改为"附加产物 + 新字段"，
  两件事各归各。
- **逐格独立缩放（每格按自己的尺寸落版）** —— 否决：同页各图字高不一致，与"同文档统一缩放"
  的既有口径（`uniformFigureZoom` 的立论：逐图独立缩放会让同文档字高不一致）冲突。
- **固定网格（如固定 2 列）** —— 否决：各视图尺寸不同，固定网格要么浪费版面、要么把小图压到
  字高不合规；网格形状改为由"统一缩放系数最大"择优。
- **把拼版信息塞进既有 `layout` 字段** —— 否决：一个字段两义，下游只能靠猜。
- **新造交付物角色值 `submission-sheet`** —— 否决：角色值是 sidecar 清单的契约，新增取值要同步
  改 fail-loud 解析器并扩大既有案卷的兼容面；拼版页本质也是"提交页"（A4 整页），归
  `submission-page` 更省且语义不偏。
- **顺带修既有单图落版页根标签缺 `>` 的问题** —— 本批**不做**：那会改单视图路径的既有产物字节
  （本任务明确要求逐字节不变）⇒ 作为已知问题记录（见下），修它需单独决策。

## Consequences

- 多视图交付多了"整页 A4"这个形态：一页装下全部视图，页码与图号体例沿用档案。
- 工具输出多了 `sheet_path`（可选字段，`outputSchema` 不参与重放请求键 ⇒ 不影响 fixture）；
  报告多了拼版页路径、网格形状、统一缩放与字高核验结论三行。
- 拼版页走**新**文件名 `-fig<N>-sheet.svg` ⇒ 与既有 `-fig<N>.svg`（多视图时带视图名后缀）、
  `-fig<N>-page.svg`、`-fig<N>-manifest.json` 互不冲突。
- 交付物清单里多一条记录（拼版页）⇒ `checkDeliverableManifest` 的清单一致性判定随之多一项
  （既有多视图 case 卷需重跑一次生成以刷新清单）。
- 拼版页**不**替代主视图的整页落版页：两者形态不同（"主视图单独一页"与"多视图共页"），
  实务里都常用；同时产出。若将来只留其一，应另开决策。

## 已知问题（诚实记账）

- **既有单图落版页（`submission-page.ts`）的根 `<svg>` 开始标签缺闭合符 `>`** ⇒ 该产出**不是
  合法 XML**（`xmllint` / `rsvg-convert` 拒绝解析；HTML 解析器会把紧随其后的 `<rect>` 吞进
  开始标签）。本批受"单视图产物逐字节不变"约束**未修**。拼版页是**新**产物，**不复制**该写法：
  根标签闭合，严格渲染器可直接打开（`tests/patent/figuregen/submission-sheet.spec.ts` 有用例
  锁住"根开始标签带 `>`"与开闭标签配平）。修既有页会改既有交付物的字节，须单独决策。
- **多视图时主视图的整页落版页仍产出**（与拼版页并存，见 Consequences 末条）。
