# Agent Note: 图外引线标号的择位引擎（候选锚点 / 碰撞规避 / 退化告警）

Status: implemented

## Problem

专利附图有两类标记画法：写在部件轮廓内（流程/框图的节点文本）与**向图外引**（机械制图常规，
零件上只画引线、标号离开图形）。后者要求标记线与主线条"不得互相妨碍"（指南一部一章 4.3），
但此前只有 CAD 路径有引线，且落位是一个**径向启发式**：

1. 方向单一——从图心指向锚点的那一个方向，没有候选、没有替换；
2. 不规避——引线可以贴着某条投影边或剖面线走（打印后分不清哪条是标记线），也可以从别的
   标号上穿过；
3. 没有退化出口——放不下就照样画出去，由 C7/C9 以 warn/fail 事后报出，但**交付物已经是坏的**；
4. 锚点在零件内部时（孔、槽、内部结构），标号被放在距锚点固定 6mm 处 ⇒ **压在图形上**
   （标号与轮廓线糊在一起），且当时没有任何规则检查这一形态。

## Decision

新增 `src/patent/figuregen/leader-line.ts`：吃**抽象几何**（点 / 矩形 / 线段）的图外引线标号
**择位引擎**（纯函数、确定性），由 CAD 渲染器 `cad/render-cad.ts` 调用，替换原径向启发式。

**候选枚举（确定性、无评分）**：引线长度由短到长按固定步进（`DEFAULT_LEADER_STEP_MM = 1.5mm`）
枚举 → 方向绕"远离图心"的基向按固定角度序（`LEADER_DIRECTIONS_DEG`＝0/±45/±90/±135/180°）
旋转；取**第一个**全部判据通过的落位。无随机、无阈值评分、无迭代收敛，同一输入永远同一结果
（快照测试的前提）。

**判据（四条，各自对应一条可陈述的要求）**：

| 判据 | 要求 |
|---|---|
| 标号框落在画幅内 | 标号不得被画幅裁掉 |
| 标号框不与障碍矩形/已放标号相交（净距 `DEFAULT_CLEARANCE_MM = 0.5mm`） | 标号不得压盖图内内容、不得与别的标号糊在一起 |
| 引线与已有线条不"共线"（夹角 < 15° **且**引线远端到该线条所在直线的垂距 < 0.7mm） | 标记线不得与主线条分不清（4.3） |
| 引线不与别的引线相交（锚点附近按间隙切掉一段后再判） | 引线之间不得交叉 |

**为什么共线判据看"远端垂距"而不是整条线段的最小距离**：引线常从主线条上（或其端点）出发，
逐段最小距离必然为 0——那样判会把"从线条上以小角度离开"的合法引线全否掉。改用远端垂距后，
要捉的三种形态（沿线重叠、顺线条延长出去、平行贴着走）都命中，而"正交穿越"（锚点在零件内部
时引线出图必然穿越轮廓，属常规制图形态）与"小角度离开"都不命中。

**退化出口**：全部候选被占时**不画引线**，标号就地落在锚点上（`degraded: true`）并产出告警；
CAD 侧由新规则 C11 报 warn、工具输出显式打印"标注择位降级"。"画不出来"必须比"画出错的"更响亮。

**钉死落位（`label_offset_mm`）照用但不静默**：调用方显式指定偏移时不择位、不规避（那是显式
指令），改为**审计**并把后果记进 `placements[].conflicts`（压盖图内内容 / 引线共线 / 引线穿标号 /
引线交叉），由新规则 C10 报 warn。引擎自行择位的落位恒无冲突（择位判据已排除）。

**顺序纪律**：钉死的标号先全部落位并登记为障碍，再做择位；落位按目标顺序返回。否则同一组输入
会因"钉死的排在后面"得到不同结果。

**画幅策略与参考实现的差异**：deepseek-harness 的 `leader-line.ts` 在放置后把画布往外扩边；
Sati 的 CAD 通路**不能**这样做——图幅必须落在受理局可印区内，故沿用既有的"渲染前预留标注带"
（构造期保证有位置），引擎在带内择位，放不下就退化。

## Alternatives considered

- **照搬 deepseek-harness 的 SVG 后处理**（解析 `<g class="node">`、重建组变换、从文本里认标号）
  ——落选：Sati 的两条渲染通路都**自己知道几何**（内置通路来自 `layoutFigure` 的节点盒，CAD 通路
  来自投影边表），锚点是结构化输入而非从 SVG 里认出来的。后处理必须重建坐标系（组变换、
  viewBox 单位换算），解析不出来的形态只能退化——多一层解析就多一类"认不出⇒标不了"，而 Sati 的
  强项恰是"构造期就知道一切"。
- **只修 C7/C9 的阈值，不引入规避**——落选：那只是让报告更准，不改变"交付物是坏的"这一事实；
  4.3 是**构造要求**而非检查要求，能构造期满足的不该推给检查期。
- **全局最优（把一组标号一起求解，最小化总引线长度）**——落选：需要搜索/迭代，确定性与"可解释
  为什么选了这个位置"都会变差，而收益只在标号极密的图上体现。贪心 + 固定候选序已能覆盖实际
  情形（同一锚点多标记时扇形展开）。
- **画幅外扩**（同参考实现）——落选：CAD 图幅受可印区约束，扩出去就是被裁；正确做法是渲染前
  预留标注带（既有机制）。
- **共线判据用"整条线段最小距离 < 线宽两倍"**——落选（实现后实测发现）：引线从主线条上出发时
  最小距离恒为 0，会把合法的斜向引线全否掉；实测在平板角点处把引线从 14° 误判为共线并强制
  旋转 45°，标号因此偏到图形另一侧。改远端垂距后同一位置回到基向。
- **引线交叉判据用原始线段**——落选（实现后实测发现）：同一锚点引出的多根引线在锚点处共点，
  原始判据把它们全判为"相交"，第二个标记必然退化。改为判定前按间隙切掉锚点附近一小段。
- **不做（诚实边界）**：引线与**其它引线之外**的图内文字（注记、尺寸标注）的避让未做——CAD 图
  在投影期不产文字面；最小线间距检查仍未做（需先重建轮廓，相邻边共享端点使逐点距离恒为 0）。

## Consequences

- **换来的**：锚点落在零件内部时，标号被推到轮廓**外**（实测平板中心锚点：标号从"压在图上"变为
  距锚点 7.5mm 的轮廓上方）；同一锚点/相邻锚点的多个标记扇形展开、互不压盖；引线不再与投影边、
  剖面线共线；放不下时明确降级并告警而不是画出坏图。CAD 侧新增 C10（钉死偏移的铁检）与 C11
  （退化可观测）两条规则，退化同时进 sidecar findings 与工具输出。
- **付出的**：CAD 输出与旧版不再逐位一致（有标注时标号位置会变）——无标注的输出逐位不变；
  `CadRenderResult.labels[]` 增 `leaderMm`/`degraded`/`conflicts` 三个字段、增 `labelWarnings`；
  择位是 O(长度档 × 8 方向 × 线条数) 的枚举，实测图上耗时可忽略。
- **未验证的边界**：真实客户图（几百条投影边 + 十几个标记）上的择位质量未实测；引擎尚未接到
  内置渲染器与 DOT 通路（那两条通路的标号仍写在节点文本内，属"图内标号"形态，接过来需要先定
  "哪些节点该外引"的语义）。
