# Agent Note: 附图默认渲染器决策（builtin 保持默认，附量化依据）

Status: implemented

## Problem

上一刀把 `graphviz-wasm` 落成可选渲染后端时，**"默认渲染器是否切换"的结论只有定性理由**（快照会全量变更、不该把可用性风险放到默认路径），没有任何量化证据：既没测过"两种后端的版面质量差在哪"，也没测过"WASM 的启动成本有多大"。方案文档 §8 因此把它列为"本轮之后建议立刻排"的独立决策——而它是另外两项（引线标号、图型扩展）的前置：那两项都要建在"默认渲染器是谁"之上。

补救过程中还查出 graphviz 通路的一个**真缺陷**（见下 "Decision 3"）：连字符节点 id 会让整条通路 fail-closed。

## Method

新增 `scripts/figure-benchmark/renderer-compare.ts`（对比脚本，**不挂 CI**——它服务一次性决策），输入是入库的确定性用例集合：合规基准 18 例 + 本脚本补的 3 例**分叉/树/汇合拓扑**（合规基准的用例是链式或单列，拿它分辨不了布局质量，而 graphviz 后端正是为分叉大图引入的）。

度量全部从**交付后的 SVG** 反推，与渲染器内部实现无关：文本框（`<text>` + 生产同源字宽度量）、连线（内置取 `<polyline>`；graphviz 取 `<g class="edge">` 内 `<path d>`，三次曲线按 1/4 采样）、节点盒（白底填充的 rect/ellipse/polygon）、打印字高（源字号 mm × 缩放）。

**预登记判据**（先写判据再看数字）：C1 契约对等（V 规则签名 / 节点回读 / 图号观测 / 安全门全等）；C2 版面不劣（三个缺陷计数不增、打印字高不降）；C3 成本（冷启动 ≤ +500ms、稳态单图 ≤ 5ms、RSS ≤ +50MB）；C4 失败面可解释（fail-loud、无静默回退）。

## Decision

**1. 默认渲染器保持 `builtin`，不切换。** 依据见下 Measurements：在 21 个用例上，graphviz 系的**缺陷计数与 builtin 打平**（文字交叠 / 标签穿线 / 边穿节点均为 0），质量优势只体现在**打印字高余量**与画幅利用率；而切换的代价是每一次交付产物的字节与版面**全量变化**（生成侧基准、dot/wasm 快照、sidecar 版面数值一并失配），并把默认路径换成"产物字节由第三方依赖版本决定"（`@viz-js/viz` 升级即改动所有附图）与"CI 覆盖更薄"（CI 无系统 dot，graphviz 通路靠 WASM 真机一例撑着）的路径。

**2. 记录 graphviz 的实测优势与代价，并给出 opt-in 判据。** 优势：同一个 16 步流程图，内置渲染器缩放后打印字高 **2.03mm**（CN 实践下限 2.0mm，余量 1.5%），`graphviz-wasm` 是 **3.13mm**（余量 57%）——这正是"附图被缩到三分之二后是否还清晰可辨"的那条线。代价：WASM 冷启动 +42ms（模块加载 18ms + 实例化在首图内）、常驻内存 +16MB、产物字节中位数 ×1.6。**判据**：当内置渲染器的打印字高接近法域下限（不足 1.2 倍）或画幅需缩到 2/3 以下时，用 `SATI_FIGURE_RENDERER=graphviz-wasm` 出图；否则保持默认。

**3. 修 graphviz 通路的 fail-closed 缺陷（连字符节点 id）。** graphviz 为避免 `--` 破坏 XML 注释，会把 `<title>` 里的 `-` 写成 `&#45;`；而 `postProcessGraphvizSvg` 是拿**未转义**的 `f1-n1` 去 `indexOf("<title>f1-n1</title>")` —— 于是**任何含连字符的节点 id 都让整条 graphviz 通路 fail-closed**，而 `f1-n1` 正是生产 id 形态（`gen-cases.ts`、工作流原子）。该缺陷在 `main` 上即存在，既有测试用的 id 全是 `start`/`step`/`check` 这类无连字符形态、且 CI 无系统 dot（真机用例自动 skip），所以一直没被抓到。改为**扫 `class="node"` 分组、取其首个子元素的 `<title>` 反转义后比对**；`dotNodeTitle` 随之删除（它的存在意味着"title 与节点 id 有字面量对应关系"，而这个前提本身就是缺陷来源）。

## Measurements

环境：macOS / Node 22.22.3 / 系统 dot 15.1.1 / `@viz-js/viz` 3.30.0 / 21 用例 × 3 后端 × repeat 3。

| 判据 | 结果 |
|---|---|
| C1 契约对等 | **通过**：21 例 × 2 后端的 V 规则签名、节点 id/ref/label 回读、图号观测、SVG 安全门全等 |
| C2 版面不劣 | **通过**：文字交叠 / 标签穿线 / 边穿节点三个计数一个都不增；打印字高 21/21 例不低于 builtin |
| C3 成本（graphviz-wasm） | **通过**：冷启动 +42ms（预算 500）、稳态 0.37–0.97ms（预算 5）、RSS +16MB（预算 50） |
| C3 成本（graphviz 子进程） | **未通过**：稳态 **87ms/图**（每图一次进程 spawn），冷启动 +95ms |
| C4 失败面 | 两后端均 fail-loud、不静默回退（既有单测断言） |

| 量 | builtin | graphviz-wasm | 说明 |
|---|---|---|---|
| 打印字高（缩放后，mm） | 1.77 – 3.70 | 2.38 – 4.94 | graphviz ≥ builtin **在全部 21 例**；典型差 1.33×（源字号 3.70mm vs 4.94mm） |
| 低于法域下限的用例数 | 1 / 21 | 1 / 21 | 都是 `block-latin-long`（US 下限 3.2mm：1.77 vs 2.38）——**graphviz 也救不了**，该例的瓶颈是长 Latin 标注推宽画幅 |
| 画幅利用率（均值） | 0.67 | 0.91 | graphviz 更少留白 |
| SVG 字节（中位） | 2455 | 3957 | graphviz 用样条采样，折线段中位 9 vs 16 |
| 稳态单图耗时 | 0.02ms | 0.37–0.97ms | 绝对量都可忽略（相对一次模型调用是秒级） |

**度量口径本身修过三处**（都在对比脚本里，且都由"跑出假阳性"驱动；不修就会把噪声当结论）：① 缩放系数跨单位制不可比（内置 px、graphviz pt），改用**打印字高（mm）**判定可读性；② 对 0.02ms 的基线用"2× 比值"判稳态退化没有意义，改用**绝对预算**（比值仍打印作参考）；③ 三个缺陷计数要求**贯穿**（两端在框外且穿过两条边），并排除**边标签**（内置靠 `paint-order="stroke"`、graphviz 靠 `<g class="edge">` 分组 + 白底垫片，两种记号都要排除）——否则"连线止于节点边框"与"graphviz 自己压在连线上的标签"会被算成缺陷，只惩罚其中一方（实测先后产生 3 处假阳性）。

## Alternatives considered

- **切换默认为 `graphviz-wasm`** — 落选。判据 C1–C4 其实**允许**它（都通过），所以这是权衡而非"不合格"：换来的只有打印字高余量与利用率，付出的是全部既有交付产物字节变更（生成侧基准 + 快照 + sidecar 版面数值）、产物可复现性由第三方依赖版本决定、以及默认路径落到 CI 覆盖更薄的一侧。当前没有"合规性"层面的收益（缺陷计数打平、法域下限的达标例数相同），不值得动默认。
- **切换默认为系统 `graphviz`（子进程）** — 落选且更明确：稳态 87ms/图（每图一次进程 spawn）超出绝对预算一个数量级，还把"有没有装 graphviz"变成默认路径的硬依赖。
- **按图自动选后端（比如字高不足时自动切 graphviz）** — 落选（本次）。自动切换会让同一份申请里的附图**出自两套布局器**（版面风格不一致），且产物字节依赖运行时环境（谁装了什么），复现性更差。改为**人工 opt-in 判据**（Decision 2），选择点暴露在调用方。
- **把渲染器做成工具 `inputSchema` 选项** — 落选（沿用 2026-08-28 与 WASM 那一刀的结论）。llm-replay 的请求键绑定工具 `inputSchema`，加一个渲染器枚举会让**每次改默认/加后端都要重录 fixture**；渲染器是运行环境属性（`SATI_FIGURE_RENDERER`），不该进模型可见契约。
- **把对比脚本挂成 CI 门禁** — 落选。它是一次性决策的证据工具：挂门禁会把"打印字高/利用率"这类**随依赖版本漂移**的量变成红绿灯（`@viz-js/viz` 升级即假红），而它要防的回归（契约对等）已由 `tests/patent/figuregen/*` 的既有单测覆盖。脚本里的纯函数（解析与计数口径）另有 `tests/scripts/figure-benchmark/renderer-compare.spec.ts` 11 例护栏。
- **保留 `dotNodeTitle` 作为快速路径（先字面量匹配、失败再解码扫描）** — 落选。它编码的正是"title 与节点 id 逐字对应"这个已被证伪的前提；留着会让下一个改动者以为存在这种对应关系。删除后 `dot.ts` 的 `escapeXmlText` 一并成为死代码，同时移除。
- **给对比补真实客户大图** — 未做（本次）。真实大图是私有数据，且需要人工 ground truth（与 `scripts/figure-benchmark/run.ts` 的分析侧基准同性质）；本次用 3 例分叉/树/汇合拓扑覆盖"分叉大图"这一形态，**边界如实声明**：结论只保证在这 21 例上成立。

## Consequences

- 默认渲染器不变 ⇒ 既有附图产物、快照、生成侧基准**零变更**；graphviz 系维持 opt-in。
- graphviz 通路对**任意节点 id**（含连字符、含 XML 特殊字符）都能注入 `data-ref`；回读的节点 id 与 `FigureSpec` 一致（此前会抛出"未找到节点 title"）。
- 新增回归 3 例：`dot.spec.ts` 两条（替身 SVG 的 `&#45;` 注入与回读、dot 真机全链路含连字符 id）+ `render-viz-wasm.spec.ts` 一条（**CI 可跑**——CI 无系统 dot，这是该缺陷类在 CI 侧的唯一覆盖）。负控制：把修复改回字面量匹配，三条全红；恢复后三份规格 33 例全绿。
- `parseFigureSvg` 的回读不变（`unescapeXml` 早已处理数字实体），`dotNodeTitle` 与 `escapeXmlText` 从 `dot.ts` 与 barrel 中移除。
- 决策的可操作性落在两处文档：`skills/patent-illustrator/SKILL.md`（何时改走 graphviz-wasm 的判据）与方案文档 §8（该项标记为已完成并指向本 note）。
- 未验证：真实客户大图上的布局质量对比（见上"未做"）；桌面端 DMG 上跑 graphviz-wasm 仍未端到端验证（沿用上一刀声明的边界）。
