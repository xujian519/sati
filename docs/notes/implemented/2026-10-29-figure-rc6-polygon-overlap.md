# Agent Note: RC6 元素重叠改用轮廓边相交（包围盒只作预筛）

Status: implemented

## Problem

P0 把 RC6 `element-overlap` 落成「两个闭合轮廓的包围盒在两轴上都相交超过 0.2 毫米」。这条
判据在合成基准集（方框类流程图）上零命中、看起来安全；第一次拿到真实交付（淄博凯诺案 4 幅
机械图）复跑时，3/4 幅被报、共 29 条发现。

逐条核对后发现：fig1 的 24 条全部是假阳性——相邻 45° 辐条的轴对齐包围盒大面积套叠
（报告写「10.9×10.9 毫米」），两个多边形本身相距很远、边与边零交点。fig1 的 26 个闭合
子路径还都装在同一个 `<path>` 里，文件没有 `data-dsh-hatch-group` 标注，于是同一条 path 内的
相邻辐条被两两配对。若维持该判据，RC6 永远不能升 `fail`，报告也会被这类噪音淹没。

## Decision

RC6 的最终判据改为**轮廓边真正互相穿过**：

- 包围盒相交（两轴均 > 0.2 毫米）只作预筛，用于快速排除不可能相交的图元；
- 预筛通过后逐边做严格相交测试：两条边必须在对方所在直线的两侧；端点相接、共线贴边、
  一件严格包含另一件（装配画法）都不算重叠；
- 原有的三类豁免不变：同一 `data-dsh-hatch-group`、两侧都无描边、严格包含；
- 报告措辞保留「轮廓重叠」，但把尺寸明确标成「包围盒相交 A×B 毫米，轮廓实测互相穿过」，
  不再把包围盒尺寸当成重叠面积。

回归用例：两根 45° 平行条，包围盒在两轴各相交约 31 用户单位、轮廓实际相距 6 用户单位，
必须不报（`render-check.spec.ts`）。

## Alternatives considered

- **保留包围盒判据、继续 `warn`** — 真实机械图 75% 的幅面被报，24/24 条可证伪；噪音会让人
  忽略真正的压叠，且该规则永远无法升级为阻断档。
- **按所属 `<path>` 分组，同 path 内的子路径不互比** — 能消掉本案例的假阳性，但会连带
  掩盖同一 path 内两个零件真实压叠的缺陷；且跨元素斜放图形的包围盒假阳性依然存在，只治标。
- **提高阈值或改成「重叠面积占比」** — 斜放零件的包围盒交叠本来就可能很大，任何阈值都无法
  把「包围盒套叠」与「轮廓相交」分开；面积比同样基于包围盒，误差同源。
- **识别旋转/斜置图形并跳过** — 用变换矩阵或包围盒长宽比作启发式，会在最需要量测的几何上
  静默不判，违背「降级但不静默」；且本案例的斜置来自顶点坐标本身，未必有 transform。
- **点采样/栅格化判重叠** — 需要栅格化器或采样密度参数，既慢又只能近似；闭合轮廓的边相交
  是精确判定，成本只有 O(边数²)。

## Consequences

- 真实语料复跑：fig1 的 24 条降为 0；机械图不再被旋转包围盒误伤，方框类流程图的判定不变。
- 代价：斜放/曲线轮廓的贴合现在只在边真正穿过时报，曲率大的曲线按顶点弦近似，可能漏报
  轻微穿插（宁可漏报也不再把正常排版报成缺陷）。
- RC6 仍定 `warn`；本次只修判据，是否升 `fail` 需要再用含真实压叠缺陷的语料量测。
