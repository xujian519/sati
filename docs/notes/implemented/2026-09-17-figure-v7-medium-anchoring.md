# Agent Note: 附图 V7 判据由画幅像素改为纸面毫米（A4 可印区锚定）

Status: implemented

## Problem

V7 的规则依据是审查指南一部一章 4.3「附图缩小到三分之二时仍应能清晰分辨图中各个细节」，
但判据用的是**画幅像素上限**（`FIGURE_CANVAS_MAX_PX = 1600`）——交付物却是 A4 打印稿。
像素与纸张之间没有换算，于是判据与它声称保护的目标脱钩：

| 流程步骤 | 画幅 | A4 纸面尺寸 | 旧 V7 |
|---|---|---|---|
| 8 步 | 238×904u | 63×239mm | 通过 |
| 12 步 | 253×1340u | 67×**355mm** | **通过（漏报）** |
| 16 步 | 253×1776u | 67×470mm | 报 V7 |

A4 可印区高 257mm，9 步以上即超出，会被打印分页**切断**（不是"不清晰"，是交付缺陷），
而旧判据要到 ~15 步才响。同向的第二种失效：同一文档内字高在 1.49mm～3.7mm 间漂移，
1600u 宽的图文字打印后仅 1.49mm（缩 2/3 后 0.99mm），旧判据对字高完全无感。

版式侧的同型缺陷：`html.ts` 只给内嵌 SVG `max-width: 100%`——只压宽不压高，纵向溢出
照样分页切断，且逐图独立缩放导致同文档字高不一致（大图字小、小图字大）。

## Decision

**判据锚定到纸张**（新 `figuregen/page-contract.ts` 为核验器与 HTML 版式的单一事实源）：

1. **页内可印性**（`metric: "page_fit"`，**fail**）：SVG 无单位宽高即 CSS px（1in = 96px），
   换算 `mm = px / 96 × 25.4` 后与 A4 可印区（170×257mm，由 `@page` 边距常量推导）比较；
   超出即 fail（会被分页切断），报文给出实际毫米与所需缩放百分比。
2. **打印字高**（`metric: "font_size"`，**warn**）：`printed = pxToMm(FIGURE_FONT_SIZE) × zoom`，
   与 `MIN_PRINTED_FONT_MM = 2.0` 比较；证据附"再缩 2/3 后"的字高，把 4.3 的三分之二规则
   落到数字上。
3. **统一缩放系数**（`uniformFigureZoom`）：取全文档各图 `min(1, 可印宽/图宽, 可印高/图高)`
   的最小值，核验器与 HTML 共用——逐图独立缩放会高估小图的打印字高，也会让同一说明书字高不一致。
4. **版式同步**：`html.ts` 按 SVG 根元素声明的画幅（单位归一：无单位/px/pt/mm/cm/in）写入
   纸面毫米定宽，并补 `max-height: <可印高>mm` 与 `break-inside: avoid`；画幅声明不可解析时
   走 CSS 兜底类（`width:auto` + `max-width:100%`），不猜测尺寸。

`figure_nos` 与规则号 `V7` 保持不变（规则依据未变），新增 `metric` 字段区分两种判定维度，
使既有消费方能按维度分流而不必解析报文文本。

## Alternatives considered

- **保留 px 阈值，只把 1600 调小到"9 步即触发"的数值** — 落选：把画幅 px 校准到某个步数只是
  在一个与交付物无关的量上拟合参数，换纸张（Letter / A4 横向）、换版式边距、换渲染器
  （graphviz 以 pt 计画幅）后立即失效；且 px 判据无法表达"字高"这第二个失效面。
- **按"缩放后字高"单一判据（把超页也降级为 warn）** — 落选：超页会被**分页切断**，是交付
  缺陷而非可接受的清晰度折中，必须 fail（且 fail 才进 HITL 决策）；字高不足则是"能看但费力"，
  保持 warn 不阻断撰写。
- **每幅图独立算缩放系数**（即只用本图尺寸） — 落选：实际排版若逐图缩放，同一说明书内字高
  不一致（大图字小、小图字大）；若排版用统一系数而核验用单图系数，核验会**高估**打印字高，
  恰好漏掉"因同文档大图而整体缩小"这一真实场景。故两侧共用 `uniformFigureZoom`。
- **在 check.ts 里直接手写 170/257/2.0 常量** — 落选：`html.ts` 的 `@page` 边距是同一组事实，
  两处各写一份即下一个漂移点（本次两处缺陷同源）；提取 `page-contract.ts` 后
  `readback-html.spec.ts` 能直接断言"版式与判据常量一致"。
- **为字高判据引入真实字体度量（字宽表/字体文件）** — 落选：与 P1-2 的字宽度量同因——渲染器
  刻意不依赖字体文件（确定性、零外部资产），字高以字号（px）+ 缩放系数近似即足以支撑
  "低于 2mm 提示拆图"的决策，不需要亚毫米精度。
- **HTML 侧改用 `zoom`/`transform: scale()` 而非毫米定宽** — 落选：打印管线（Chromium
  headless）对 `transform` 的分页行为不稳定，且 `transform` 不改变布局盒尺寸，会让
  `break-inside: avoid` 失去意义。

## Consequences

**换来**：V7 从"像素代理"变成可解释的纸面判据——9 步以上 TB 流程图会被拦下（附实际毫米），
A4 稿字高可判、同文档字高一致；核验阈值与版式常量同源，两处不会再各自漂移。

**付出**：

- **语义变更（破坏性）**：既有按 px 表述的 V7 用例与用户预期需按新语义重读；`FIGURE_CANVAS_MAX_PX`
  导出被移除（barrel 同步）——外部若 import 该常量会编译失败（fail-loud，不静默变义）。
- 12 步级流程图从"通过"变为 **fail**：这是判据修正而非回归，但会让既有案卷的附图首次被拦，
  需要拆图（预期行为，HITL 可放行）。
- 字高 warn 阈值 2.0mm 是**初值**（常量可调），未经打印实物验证；正式提交前仍需代理师复核。
- 统一缩放意味着"文档内任一图超页"会连带拉低同文档其他图的字高判定（诚实反映实际排版，
  但单图自身尺寸无法预测该结果）。
