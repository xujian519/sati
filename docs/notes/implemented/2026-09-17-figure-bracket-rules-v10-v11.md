# Agent Note: 附图标记括号规则按面判定（V10 权利要求漏括号 / V11 正文多括号）

Status: implemented

## Problem

细则第 22 条要求**权利要求**中的附图标记置于括号内；而**说明书正文**的惯例相反——
"名称+数字"不加括号（本项目知识库卡片 `255359a2208c6957` 已核）。两种规则相反，
而核验器的入参 `spec_text` 是"权利要求书 + 说明书"的**混合体**：

- 整体扫括号（现状 `extractBracketRefs`）⇒ 既漏掉"权利要求漏括号"这类**可确定性判定**的
  违规，也让 V3 只能保守降级为 WARN（它无法区分"括号标记"来自哪一面）；
- 若简单地对整体文本同时施加两条相反规则 ⇒ 必然互相误伤（正文的括号形被 V10 判违规，
  权利要求的括号形被 V11 判"多余"）。

## Decision

新增启发式分节 `figuregen/spec-sections.ts`（按小节标题定位，**零 schema 变更**），
在分节成功时启用两条新规则：

- **V10（fail）**：权利要求面出现"组件名 + 裸数字"形式引用图内标记 ⇒ 必须加括号。
  判据有意收窄：只认**紧跟列举分隔符或行尾**的裸标记
  （`[\u4e00-\u9fff]{2,}\s*<ref>(?=\s*[，,；;、。：:]|$)`），以免把数量词（"共 20 个"）、
  数值范围（"20℃至 90℃"）、步骤号（"S20"）判成附图标记。
- **V11（warn）**：说明书正文面以括号形式引用图内标记 ⇒ 惯例应为"名称+数字"。
  排除公式/步骤/图号编号（`式(1)`/`步骤(1)`/`图(1)` 等前缀词）与**附图说明小节**
  （其式样本就是"1—混料器"，不适用正文规则）。
- **分节失败如实降级**：两个面都取不到时 V10/V11 整体跳过，并在 `FigureCheckResult.specFaces`
  里写明 `sectioned: false` 与原因；附图门与 `patent_figure_check` 的报告都会打印这一行
  （"未分节（V10/V11 未生效）——<原因>"）。**不猜面判违规**。
- `skipTextRules`（生成期无文本）时 `specFaces` 为 undefined。

## Alternatives considered

- **新增显式入参 `claims_text` / `description_text`（要求调用方分面）** — 落选（评审决策 D3）：
  改 `inputSchema` 就要重录 llm-replay fixture，而"分成两面"是模型容易做错、且可被本地启发式
  完成的事；先走零 schema 的启发式，等 CAD 工具暴露面那批 schema 变更时再合并加入（一次重录
  覆盖两处变更）。
- **不分面，改为单一"括号一致性"规则（同一标记在全文要么全括号要么全不括号）** — 落选：
  两种形态并存恰恰是**正确**的（权利要求括号、正文裸数字），一致性规则会把正确写法判成违规。
- **V10 用更宽的判据（"名称+裸数字"不限后随字符）** — 落选：会把"包括20个处理单元""温度为20℃"
  判成附图标记，而 V10 是 **fail** 级且已接入自动门禁（figure-gate 会据此挂 HITL），宽判据的
  假阳性会直接拦住合法案卷。收窄的代价是漏掉"句中夹缝"形态（如"所述壳体10连接…"），
  已在规则注释与报告面注明：这是覆盖率换取正确率的取舍。
- **V10 降级为 warn（避免任何假拦）** — 落选：细则第 22 条是**形式硬性要求**，且收窄后的判据
  只在"紧跟分隔符/行尾"时命中，实测的数量词/范围/步骤号用例均不误报；降级会让一条可确定性
  判定的形式缺陷变成"看看就好"。
- **V11 覆盖全部正文（含附图说明小节）** — 落选：附图说明的式样是"1—混料器"（标记在前、
  全角破折号连接），若只排除"括号形"而不管小节归属，会把该小节里合法的括号引用（如
  "图1（剖视图）"这类写法）误报；按小节整体排除更贴合指南对附图说明的写法约定。
- **为 V11 引入 OCR/渲染级判定（真实括号字形 vs 全角半角）** — 落选：全角/半角括号在本规则
  下语义相同（正则已同时接受），字形差异不改变"括号内是标记"这一事实，引入渲染判定只增加
  依赖。

## Consequences

**换来**：两条可确定性判定的括号规则首次生效——权利要求漏括号会**阻断**（fail → 附图门挂 HITL），
正文多括号会提示；分节结论随 `figure-check.json` 落盘，审计时能看出"V10/V11 是否参与过判定"。

**付出**：

- 分节是启发式的：依赖小节标题（`权利要求书`/`说明书`/`技术领域`/`具体实施方式`/…）或
  首段"1. … 其特征在于"形态；标题写法非常规（如自定义模板只有"权利要求"二字）会分节失败 ⇒
  V10/V11 静默（报告注明）。**不新增猜测路径**是有意选择（漏报优于误报）。
- V10 的收窄判据漏掉"句中夹缝"形态的漏括号（标注在规则注释里）；扩大判据需要先有
  "哪些中文量词不是名词"的确定性数据，本轮不具备。
- V10 是 fail 级 ⇒ 已接入自动门禁后，历史案卷若权利要求用裸数字引用标记会首次被拦
  （属判据修正，HITL 可放行）。
